# 実績のまとめ変更（一括編集）モックアップ

## 目的

実績レコードは現状 1 件ずつしか編集・削除できない（`js/actual.js` リストビューの「編集」「削除」、タイムラインのバー単位 D&D）。
「誤った版数で 1 週間分登録した」「その他工数で入れた実績を後から版数・工程に紐付けたい」「担当者名の表記ゆれを直したい」
「週ごと日付をずらしたい」といった **複数件を同じ規則でまとめて変える** 操作を、どの UI で提供するかを比べる。

## 確認方法

ブラウザで `index.html` を開く。実物の `../../style.css` を読み込むため、色・フォント・部品は本番と同一。

- 3 案とも **同じ 16 件の実績データ・同じ課題** から始まる（インタラクティブに操作できる）。翌週 8/24〜 の追補は正しく V2.4 で登録済み、という筋書き
- 共通の課題: 田中さんが 8/17〜8/21 に「V2.3 帳票A出力改修」として登録した 5 件を「V2.4 帳票A出力改修（追補）」へ付け替える。
  同じ週の田中さんの「打ち合わせ」（その他工数）1 件は変えてはいけない
- 右側の **操作ログ**（ステップ数）と **課題の達成度**（3 項目の自動判定）で、案ごとの到達経路を客観的に見比べられる
- 「表示幅」で PC / スマホ（390px）を切替。モーダルと下部バーの収まりを比較できる
- 各案は「リセット」でいつでも初期状態に戻せる

## 各案

| 案 | 操作 | 向いている場面 | 弱点 | 既存の前見本 |
|----|------|----------------|------|--------------|
| 案1 選んで一括編集 | リストで ✓ を付け → 下部バー →「変えたい項目だけ」を指定するモーダル。全選択・Shift 範囲選択。別日に複製／削除も同じバーから | 目で確かめながらの付け替え・削除・日付移動 | 件数が多いと選択が手間 | `js/estimate-selection.js`（作業月選択モード） |
| 案2 条件で置き換え | 期間・担当・版数・対応名・工程で対象を絞る → 該当件数と一覧ハイライトを確認 → 置換内容を指定 | 件数が多い機械的な置換（表記ゆれ統一、版数の付け直し） | 対象が条件式の裏に隠れ、誤爆時の影響が大きい | `js/merge-core.js`（差分プレビュー） |
| 案3 表で直接編集 | 一覧のセルをそのまま入力欄にし、変更セルを色で示して一括保存。列ヘッダーの「列を一括で…」で表示中の全行を同じ値に | 行ごとに違う値を直す個別修正 | 「同じ値をまとめて」が本題からずれる。列一括は無関係な行にも入る。モバイルで狙いにくい | `js/report.js`（見込残存の一括編集） |

3 案に共通する設計上の約束（どの案でも守る）:

- 適用前に **変更前 → 変更後のプレビュー** を必ず出す
- 適用は **1 件の Undo アクション**（`actual_bulk_edit`）として記録し、1 回で全件戻せる
- バリデーションは `saveActualEdit` と同じ（版数ありなら工程必須、工数 > 0）
- `remainingEstimates` / `schedules` は触らない（キー変更で孤立した見込残存は既存の `cleanupOrphanedRemainingEstimates` に委ねる）

## 案1 の拡張（2026-08-29 案1 採用後に追加）

### 条件で選択…（案2 の吸収）

選択バーのボタン 1 つ。期間・担当・版数・対応名・工程で絞り、該当件数と一覧のハイライトを見ながら
「選択に追加」「この条件だけを選択」。**置き換える内容は持たない**（適用は一括編集モーダル一本）ので、
結果は常に一覧上の ✓ として見え、手選択と混ぜられる。表示フィルタ外の該当があれば「表示外 N 件を含む」と注記する。

### タイムライン（ガント）からの選択

`js/actual-timeline.js` の調査結果（2026-08-29、行番号は当日時点）:

- ガントは `mergeAdjacentActuals`（:2981）で **同じ担当・版数・対応名の暦日連続を既に 1 本のバーに結合**し、
  `.actual-tl-bar.actual.merged` に `data-actual-ids`（複数 id）を持つ。「一続きの複数作業」= このバー 1 本
- 結合キーに工程が無いので PG→PT→IT と工程が変わっても 1 本。土日を挟むと別バー（暦日連続のみ）
- 既存操作: クリック → 詳細パネル（複数 id は `showGroupDetailPanel` :2066、**一括アクション無し**）、
  マウスドラッグ 5px → バー移動（複数 id でも `ids[0]` 1 件しか動かない）、タッチ長押し 400ms → ドラッグ、
  空エリアドラッグ → 作成、コンテナ横スワイプ → 月移動。`contextmenu` / `dblclick` / Ctrl・Shift+クリックは未使用
- 採る選択ジェスチャ: **バークリック（既存の詳細パネル）にメニュー項目を追加** — 「このバーの N 件を選択」
  「同じ対応をすべて選択（本人／全員）」「この N 件を一括編集…」。Ctrl/Shift+クリックで即トグル、右クリックでも同じメニュー。
  長押し・横ドラッグ系は既存操作と衝突するため使わない
- 選択状態はリストと共有（`selectedActualIds`）。バーに `.selected` を付け、下部の選択バーも共通

## デザイン上の判断

- 下部の作業トレイ（選択バー／保存バー）だけを **ダーク（`--text-primary`）** にした。Quiet Depth のクリーム＋深緑の面に対し、
  「今だけ現れている操作レイヤー」であることを一目で区別するため。それ以外はすべて既存トークンで組んでいる
- 一括編集モーダルの各項目は「変更しない／変更する」のセグメントで、**触らない項目は触らない**ことを明示する
  （空欄 = 変更なし、という暗黙ルールを避ける）
- 各項目に「現在: V2.3 ×5」のように選択中の値の内訳を出し、混在している項目を上書きする前に気づけるようにする

## 方針（2026-08-29 決定: 案1 を採用）

**案1 を土台にし、案2 の「条件で絞る」を案1 の選択バーに「条件で選択…」として吸収する。
タイムライン（ガント）のバーからも同じ選択に合流させる。**
対象の集め方は 3 通り（手で ✓／条件で絞る／バー）、適用エンジン（パッチ適用 + 一括 Undo）は 1 つ。
案3 は「まとめて同じ値にする」用途からずれるため見送り。

段階分け（想定）:

1. リスト選択モード + 一括編集（版数／対応名／工程／担当／レビュー／日付の指定・シフト）+ 一括削除 + 一括 Undo + テスト
2. 「条件で選択」ポップオーバー、別日に複製
3. 工数の倍率・按分、カレンダー／タイムラインからの選択
