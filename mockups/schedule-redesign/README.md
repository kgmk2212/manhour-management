# スケジュール機能の刷新 — 案の比較モックアップ

BACKLOG **B-010**（スケジュール機能のガント/WBS化）。現行のスケジュールタブ（`index.html` `#schedule`、`js/schedule.js`、
`js/schedule-render.js` の Canvas ガント）を「どこまで作り直すか」で 3 段階の案に分け、同じデータ・同じ課題で見比べる。

## 目的

- 現行ガントは「誰が何をいつまでに」を示すが、**同じ人の並行予定が重なって読めず、1 日の負荷（超過・空き）が見えない**。
- 仕様書（`docs/GANTT_CHART_SPEC.md` §2.1.1）の「計画バー ＋ 実績バーの 2 層」は未実装で、計画と実績が 1 本に混ざる。
- 「いつやるか」を見積の**作業月**と予定の**日付**で別々に入力し連動しない（B-047 と表裏）。
- 以上を、現行の磨き込み（案A）／見る単位を変える（案B）／両方を役割分担させる（案C）の 3 案で解く。

## 現状の課題（コードと画面で確認済み）

| 課題 | 根拠 |
|------|------|
| 担当者行で並行予定が重ね描きされる | `js/schedule-render.js:956-962`（開始日昇順に描くだけで、レーン分割が無い） |
| 1 日の負荷が見えない | バーは期間のみ。日ごとの時間はどこにも描かれない |

| 遅延判定の二重実装ほか | B-027 / B-029 / B-033 / B-040（BACKLOG 参照） |

## 案B・案C の操作モデル

- **タップ＝選ぶ**。予定の色をタップするとインスペクタに その日の時間・全体の予定/実績/残り・期間・状態 が出る。
  空いているセルをタップすると、その日の内訳と空き時間。
- **移す＝選ぶ → 行き先**。「この日の分を別の日へ移す」を押すと、同じ担当者の営業日が緑枠の「ここへ」になり、
  インスペクタにも次の営業日 6 日が「移した後の負荷」付きで並ぶ（超過するなら赤）。どちらをタップしても同じ。
  ドラッグは使わない（`js/actual-timeline.js` の長押し・スワイプ衝突の前例を避ける）。
- **Undo**。移動・反映のあとはトーストに「元に戻す」。
- **作業月の導出**。予定の `daily` を月で集計した月の集合を「予定から」とし、見積の `workMonths` と一致すれば「一致」、
  異なれば「ずれ」、予定が無ければ「未スケジュール」。「見積に反映」は `workMonths` を導出値で置き換える
  （`monthlyHours` の按分は本実装では `splitHoursEvenly` を使う）。
- **スマホ**（≤ 768px）は格子ではなく、担当者チップで切り替える **1 人分の 2 週間アジェンダ**。各日に 8 時間の横棒（超過は右端が赤）と
  予定の一覧。項目をタップすると下からシートが出て、同じインスペクタ（移す・Undo）が使える。シートは Dock（60px）の上に置く。

## データモデルの仮定

- 予定レコードは現行の `{version, task, process, member, isReview, startDate, endDate, estimatedHours, status, ...}` に
  **日別配分 `daily: { 'YYYY-MM-DD': hours }`** を足す。`startDate/endDate` は `daily` のキーの最小・最大で導出できる。
- `daily` を持たない既存レコードは、読み込み時に営業日（土日・祝日・会社休日・本人の休暇を除く）で `estimatedHours` を均等配分して同じ形に変換する
  （後方互換。B-041① の未丸め保存を繰り返さないため 0.25h 刻みで丸める）。
- 結合キーは現行どおり `version + task + process + member (+ isReview)`。案A はデータを変えない。

## デザイン上の判断

- 色は `../../style.css` のトークンだけで組み、新しく足したのは **タスク色 4 つ**（緑 `--accent`・青 `--info`・琥珀 `--accent-secondary`・紫 `#6B4E8E`）と
  **休暇のハッチ**（`--accent-secondary` の斜線）。危険色は超過・遅延・計画外の実績にだけ使う。
- 一点だけ目立たせる要素は案ごとに 1 つ:
  - 案A: **計画バーの底に乗る実績の刻み**。日ごとの高さが時間、赤い斜線が計画外の日。
  - 案B: **8 時間の器**。破線の縁と、縁を越えた赤い数字。空いている器がそのまま「入れられる場所」に見える。
  - 案C: **ヒンジ**（計画ボード ⇄ 進捗ガント）と、画面をまたいで続く選択（選んだ予定以外が沈む）。
- レビュー予定は斜めストライプ、完了は「✓」、遅延は「!」と左の赤い縁。色だけに頼らない。
- 描画は Canvas ではなく DOM（CSS Grid ＋ absolute）。本実装でも DOM 化を推奨する（テーマ連動・キーボード操作・Playwright 検証が素直になる。
  B-029 のような `--gantt-scale` 換算漏れも構造的に起きない）。
- 部品はすべて `common.js` に集約し、案C は案A のガントと案B の格子をそのまま組み合わせている。採用後は `sr-*` の部品を `style.css` と
  `js/schedule-*.js` へ移植する。

## 推奨: 案C を段階導入する

1. **案A の核を現行ガントに入れる**（レーン分割・計画/実績 2 層・負荷帯・工程チップ・スケール切替）。同時に
   B-027 / B-029 / B-033 / B-040 と会社休日判定を直す。データ変更なし。単独で価値があり、②を待たない。
2. **計画ボードを新設**し、担当者別ビューを置き換える。予定に `daily` を追加（無ければ均等配分で読む）。スマホはアジェンダ。
3. **作業月の導出連携**。まず「予定から見た作業月」を見積側に提示して 1 タップ反映、安定したら導出に切り替える。B-047 の設計と合流させる。

採用が決まったら `docs/superpowers/specs/` に設計書を書き、本 README と相互リンクする。
