見積の「工程ごとの作業月」設定 UI 刷新 — 案の比較

見積登録／全工程を編集モーダルで、工程ごとの作業月を 開始 select 〜 終了 select で選ぶ現状（単一月でも 2 つ触る・2ヶ月期間では跨げない・スマホで月が読めない）を置き換える 3 案。すべて同じ 8 行の見積と同じ課題から始まり、右の操作ログと達成判定で手数を比べられる。

共通の課題（4 つとも満たすまでの操作回数を比べる）
V2.4 帳票A出力改修。作業期間 2026年8月〜11月。PG には田中・佐藤の 2 人とレビュー（鈴木）が付いている。初期値はウォーターフォール式の既定。
  1. PG の田中・佐藤を 8〜10月（3ヶ月）にする
  2. PG のレビュー（鈴木）は 10月だけにする
  3. IT（佐藤）を 10月から 11月へ動かす
  4. ほかの行の月と、各行の合計時間は変えない

現状開始〜終了の select（比較基準）

6操作 ／ タップ換算 12

行ごとに 開始・終了 の 2 select。担当者行・レビュー行にも同じ select が並び、同じ月を人数分選ぶ。スマホでは select が文字幅より狭くなり月が読めない（B-046）。

 推奨

案A 月チップのレールタップで 1 月、なぞって範囲

4操作 ／ タップ換算 4

行の上に期間内の月を並べる。タップした月だけになり、なぞった範囲が連続月になる。担当者行・レビュー行は工程に連動（鎖で個別化）。ドラッグ無しでも全操作が完了する。

案B ミニガントのバーバーを動かす・伸ばす

5操作 ／ タップ換算 5

各行が 1 本のバー。本体ドラッグで移動、両端のつまみで伸縮、空いている月をタップで広げる。バーの長さが期間なので表がガントとして読めるが、伸縮はドラッグ前提。

案C 工程×月マトリクス月ごとの工数を直接入力

9操作 ／ タップ換算 17

月を列にし、セルに工数を直接入れる。値のある月が作業月。月別配分（monthlyHours）まで一度に決められるが、月を動かすだけでも数値を打ち直す。スマホは横スクロール。
数値は Playwright で共通課題を最短手順で操作したときの計測値（2026-09-12）。タップ換算は タップ・ドラッグ = 1、select の変更・セル入力 = 2。

推奨: 案A を土台に、月別配分は案C の考え方を後付けする

課題の 2 つ（単一月の手間・視覚的でない）を最少手数で解き、ドラッグ無しで全操作が終わるのは案A だけ。案B の「長さが見える」良さは、案A でも連続月が 1 本のピルに溶けて見えるので大半を吸収できる。案C が解く「月別配分」は今回の課題の外側にあり、必要になったときに案A の行へ「配分…」の入力欄（既存の単一見積編集モーダルと同じ 均等／手動）を足す方が、毎回の入力量を増やさずに済む。詳細は README.md。
