# 工数入力UX改善モックアップ（ワンタップ工数ボタン＋合計表示）

## 目的

工数入力が「数値の手打ち／スピナー連打」しかなく、入力中に1日の合計や残りが見えない問題を解消する。

## 現状の課題（調査で確認した客観的事実）

- 工数欄はほぼ素の `<input type="number">` のみ。補助ボタンが付くのはタイムラインのタスクピッカー（`atlTpHours`）だけ。
- 刻みが不統一（実績 `editActualHours` は 0.25、その他作業 `meetingHours`/`otherWorkHours` は 0.5）。
- `getRemainingDayHours()`（1日8h − 当日登録済み）は新規実績のデフォルト値計算にのみ使われ、モーダル内に合計・残りの表示はない。

## 採用方向（2026-06-16 ユーザー選択 → 2026-08-19 選定やり直し）

当初は **ワンタップ工数ボタン ＋ 合計表示** が採用方向だったが、2026-08-19 にユーザーより
「ワンタップボタンだけでは数値が足りない。0.25刻みの全値に対応でき、操作しやすく見た目もすっきりした方式を、
全方式を実操作して・実データに近い状態で比較して決めたい」との要望があり、選定をやり直し中。

### interactive.html（2026-08-19・選定用）

5方式すべてを実際に操作して比較できるページ。共通条件: 0.25h刻み全値（0.25〜16h）対応・「残りNh」ワンタップ・「登録済＋今回＝合計/8h」表示。
シナリオ切替（朝イチ0h／日中4.5h／夕方7.75h／満了8h）で、当日の登録済みデータに応じたデフォルト値・残り表示・超過表示を実データ相当で確認できる。

| 案 | 方式 | 特徴 |
|----|------|------|
| 案1 | クイックチップ＋ステッパー | よく使う値は1タップ、半端は −/＋（長押し連続）・直接入力 |
| 案2 | 「時間」＋「端数」2段チップ | どの値も常に2タップで確定 |
| 案3 | 中央ホイール | 現在値を常に中央表示（ユーザー原案の具現化）。スクロール/クリック |
| 案4 | 現行ドロップダウン＋チップ | 最小変更の基準案 |
| 案5 | スライダー＋微調整 | ドラッグ＋ −/＋。1日の中の量が視覚化される |

## 確認方法

ブラウザで `index.html` を開く。実物の `../../style.css` を読み込むため、色・トーンは本番と同一。
数字ボタンを押すと工数欄に値が入り、下の合計表示がその場で更新される（超過すると赤）。

  - ※ その他作業まわりは別セッションが nonProject 機能を改修中のため、衝突回避のうえ後追いで対応する。
