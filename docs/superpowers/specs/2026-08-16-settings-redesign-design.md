# 設定タブ再構築 設計書（カテゴリナビ切替）

- 日付: 2026-08-16
- ブランチ: `experiment/ui-scaling`
- ステータス: ユーザー承認済み（構造A案・分類マッピング・自律進行の承認あり）

## 背景と課題

設定タブ（`index.html` の `#settings`）は 12 セクションが 1 カラムで縦に並び、以下の問題がある。

1. **目的の設定が見つからない** — 並び順に論理がなく、スクロールで探すしかない
2. **説明が冗長・難解** — 長文説明・箇条書き注意書きが多く、「Phase 1/2/3」など内部用語が露出
3. **項目が多すぎる** — 滅多に触らない設定が常時見えている
4. **分類が怪しい** — 「マトリクス表示」「表示形式」などセクション境界が恣意的
5. **UI パターン不統一** — `.setting-row` 形式と `form-group`＋縦積みラジオ形式が混在、
   「設定を適用」ボタンが担当者表示順にだけ存在（他は自動保存）

## 決定事項

### 構造: カテゴリナビ切替（A案）

- 設定ページ内に**カテゴリナビ**を置き、選択したカテゴリのセクション群だけを表示する
- PC: 左に縦ナビ（sticky）＋右コンテンツの 2 ペイン
- モバイル: ナビを横スクロールのチップ列に変換
- 初期表示は「外観」。最後に開いたカテゴリを localStorage に記憶して復元
- 機能削減はしない。滅多に触らない項目は「詳細」カテゴリに退避（承認済み方針）

### 分類マッピング（5カテゴリ）

| カテゴリ | 項目（現行の所属セクション） |
|---------|------|
| 外観 | アクセントカラー（テーマカラー）／ グラフカラーパターン＋プレビュー ／ スケジュールバーの色 |
| 表示 | 見積一覧の表示形式・レポートの表示形式・月標準工数の表示（表示形式）／ 月ごとの色分け・レポートマトリクスの背景色・進捗バー表示＋サブ項目（スタイル・%表示）・見積/実績の表示形式（マトリクス表示）／ 担当者表示順（担当者表示順） |
| レポート分析 | 分析機能オン/オフ 7 項目（レポート分析機能。**Phase 1/2/3 見出しを廃止**し「基本指標／グラフ／高度な分析」に改名）／ 版数別タスク構成比の表示形式（分析タブ） |
| データ | 自動バックアップ ／ 会社休日設定 |
| 詳細 | フィルタバー（表示モード・ページ内セグメントボタン）／ クイック入力の前回モード記憶 ／ デバッグモード ／ 開発中の機能を表示 |

- 従属オプション（進捗バーのスタイル・%表示）は親項目の直下に**インデント付きサブ行**として配置。
  親子を別カテゴリに分離しない。

### 行パターンと文言

- 全項目を `.setting-row` 形式に統一: 左＝ラベル＋**1 行説明**、右＝コントロール
- 長文説明・箇条書きは要点 1 行に圧縮する。挙動理解に必須の注意だけ説明文に残す
- 縦積みラジオ廃止: **2〜3 択はセグメントコントロール**（新規 CSS コンポーネント）、
  **4 択以上はセレクト**に統一
- 「設定を適用」ボタン（`btnUpdateAllDisplays`）を廃止し、担当者表示順（`memberOrder`）は
  change 時の自動適用に統一
- インライン style を全廃してクラスベースにする。style.css の inline-style セレクタ依存の
  モバイルハック（`div[style*="font-size: calc(15.5px"]` 等）は新クラスに置換

## 技術方針（互換性の担保）

- 設定入力要素の `id` / `name` / `value` は**全て不変**。15 の JS ファイルから参照されているため、
  変更するのは周辺マークアップと class のみ
- 例外は「設定を適用」廃止に伴う `memberOrder` の自動適用バインドのみ
  （`events.js` の `btnUpdateAllDisplays` クリックバインドを `memberOrder` の change に差し替え。
  互換のため隠し要素として `btnUpdateAllDisplays` を残すか、JS 側の参照を全て除去するかは実装時に判断）
- 既存の隠し互換要素（`themeColor` / `themePattern` / `themeTabColor` / `themeBackgroundColor` /
  `tabBarAlwaysVisible` / `tabFilterAlwaysExpanded` / `tabFilterButtonStyle` / `tabFilterLayout` /
  `mobileTabDesign`）はそのまま維持
- カテゴリ切替は `ui.js` に小関数を追加（イベント委譲）。localStorage キーは `constants.js` に定数追加
- セグメントコントロールは**見た目だけの包装**とし、内部は既存の radio input を visually-hidden で保持
  （JS の `querySelector('input[name=...]:checked')` 等が無変更で動くこと）

## 検証（/verify-ui）

Playwright による機械判定で以下を確認して PASS とする。

1. 全設定入力要素の存在（再構築前の ID 一覧と網羅比較）
2. カテゴリナビ切替で対象カテゴリのみ表示される
3. 代表設定の変更 → localStorage 反映 → リロード後の復元
4. 担当者表示順の自動適用（ボタンなしで反映される）
5. モバイルビューポートでチップナビが機能する

## 対象ファイル

- `index.html` — `#settings` 内の再構築
- `style.css` — ナビ／セグメント／サブ行スタイル追加、旧ハック置換
- `js/ui.js` — カテゴリ切替
- `js/constants.js` — localStorage キー定数
- `js/events.js` — memberOrder 自動適用への差し替え

## やらないこと（YAGNI）

- 設定内検索（C案）— カテゴリ化で十分と判断。必要になれば後付け可能
- 設定項目の削除・既定値固定
- 設定値スキーマや保存方式の変更
